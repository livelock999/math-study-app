# 小1 さんすう・こくご れんしゅう（MVP）

Python + Streamlit の、5・10・20問ずつ学習するWebアプリです。
計算問題・3つの数・穴埋め・文章題・3つの数の文章題、たし算・ひき算・ミックス、10まで・20まで、結果表示、間違い問題の再練習に対応します。
学習レポートでは保存した回答から現状を自動評価し、おすすめの練習を開始できます。

## 外出先のiPhone・iPadから使う（クラウド）

Streamlit Community Cloudへ公開し、履歴はSupabaseに保存する構成を用意しています。
クラウドURLをSafariで開けば、PCが停止しているときや別のWi-Fiでも利用できます。
ローカルの `127.0.0.1` URLはiPhoneからは使えません。

1. 新規プロジェクトでは `supabase_setup.sql` をSupabaseのSQL Editorで実行します。
   算数・国語の履歴と学年表示設定をまとめて作成します。既存プロジェクトの追加更新は
   `supabase_attempts.sql`、`supabase_japanese.sql`、`supabase_profiles.sql` を使用できます。
   段階ヒント・学習目標・問題報告の追加更新は `supabase_learning_extensions.sql` を実行してからアプリを更新します。
   学校で習う範囲の追加更新は `supabase_school_scope.sql` を実行してから関連ファイルを公開します。
   履歴のJSON復元は `supabase_history_restore.sql` をSQL Editorで実行してから関連ファイルを公開します。
   穴埋め・図・3つの数・計算カードをまとめて更新する場合は、`supabase_math_visuals.sql` →
   `supabase_three_numbers.sql` → `supabase_flashcards.sql` → 最新の `supabase_history_restore.sql` →
   アプリ更新・再起動の順です。追加列はNULL許容で、旧履歴はNULLとして保持します。
   3つの数の文章題も同じ列を使います。更新版の復元SQLは新しい問題形式を受け付けます。
   列追加のSQLと復元関数の更新は、既存回答を変更・削除しません。
   既存の履歴は保持し、以前のヒント段階はNULL（記録なし）のままです。
   新しい保存先へ既存の履歴は自動移行されません。接続先を変更する前に旧保存先と履歴の引き継ぎを確認してください。
   心電図appと同じプロジェクトでも専用の `math_attempts` テーブルに保存します。
2. GitHubの算数appリポジトリをStreamlit Community Cloudからデプロイします。
   ブランチは `main`、起動ファイルは `app.py`、Pythonは3.12を指定します。
3. Advanced settings / Secrets に `secrets.example.toml` の4項目を設定します。
   `MATH_REQUIRE_PASSWORD = true` にし、家族用の長めのパスワードを設定します。
   Supabase URLとサーバー用 `sb_secret_...` キーも入力します。
   本物のキーとパスワードはチャットやGitHubへ貼らないでください。
4. 発行されたHTTPS URLをSafariで開き、家族用パスワードを入力します。
   名前をタップして学習し、必要ならSafariの共有メニューからホーム画面へ追加します。

数字入力欄はタッチ端末の数字キーボードに対応し、「こたえる」「つぎへ」のボタンでも操作できます。
iPhone幅390pxとiPad幅768pxで表示を検証しています。実機Safariとソフトキーボードの挙動は
公開後に実機で確認してください。ホーム画面へ追加しても、ネット接続が必要です。

公開時は家族用パスワードの設定が必要です。必須モードでパスワードが未設定なら学習画面を開きません。
Supabase設定の片方だけがある場合はエラーで止まり、クラウド保存に失敗してもSQLiteへ切り替えません。
Supabase未設定時だけローカルSQLiteを使います。クラウド運用では必ず両項目を設定してください。
既存のローカル履歴は自動移行しません。

Streamlit Cloudのローカルファイル保存は永続性が保証されないため、外部DBを使用します。
参考：[Streamlitのデータ接続](https://docs.streamlit.io/develop/concepts/connections/connecting-to-data)

## 起動方法（Windows / PowerShell）

Python 3.10以上を用意し、このフォルダーで次を実行します。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

ブラウザーで http://localhost:8501 を開いてください。
この作業で作成済みの `.venv` があれば、最後のコマンドだけで起動できます。

## 操作

### けいさんカード

算数の設定画面で「けいさんカードを はじめる」を選びます。1〜9同士のたし算で、
最初の答え範囲は11〜18、20問です。答え範囲2〜18、問題数、順番／シャッフルを選べます。
順番は答え・左の数・右の数の順。同じ範囲のカードが不足する場合はデッキを繰り返します。
声、数字キー＋Enter、画面テンキーで回答し、保存が成功すると短い正誤表示の後に自動で次へ進みます。
間違いも続けて出題し、終了後に間違えたカードだけ再練習できます。

音声は対応ブラウザーの SpeechRecognition を使い、開始ボタンからマイクを有効にします。
ブラウザーの認識サービスが音声を処理する場合があります。アプリは音声ファイルを保存せず、
認識された文字・数値・入力方法・失敗回数を回答履歴に保存します。
数字に変換できない声は採点・回答保存せず、同じ問題に戻ります。
不正解になる認識値は「○って いった？」で確認し、聞き違いなら言い直せます。
正解になる数値は自動で採点するため、認識誤りを完全に検出するものではありません。
音声非対応・許可がない・通信に失敗した場合は数字キーや画面テンキーを使えます。
対応例はChromeとSafariですが、端末・言語設定などに左右されるため実機で確認してください。

カードの履歴も既存の `math_attempts` / SQLite `attempts` に保存します。
`learning_mode=flashcard` がモード、`selection_type=normal/retry` が出題理由です。
通常練習は `learning_mode=normal`、旧履歴はNULLのままです。
音声由来の `recognized_text`、`parsed_answer`、`recognition_success` は声で回答したときだけ記録。
キーボード等へ切り替えても、先行する音声失敗の `recognition_retry_count` は保持します。
初回の正誤を `first_attempt_correct` に保持し、再回答は別回答ID・別セッションで保存します。
答え範囲、問題属性、出題順、表示から回答確定までの時間も保存します。
認識待ち・言い直し・確認は回答時間に含むため、入力方法と条件を揃えて速さを比較してください。

終了画面と「計算カードのレポート」で正答率・平均時間、問題別・構造別・日別の成績を確認できます。
通常の習熟評価・おまかせ難易度とは別集計で、日々の学習量・履歴・復習は既存の仕組みに統合します。
保護者のテスト中はカード回答も保存しません。流暢性スコアと苦手優先のカード出題は今後の拡張です。

公開前に `supabase_flashcards.sql`、続いて最新の `supabase_history_restore.sql` を実行します。
古い環境では `supabase_math_visuals.sql` と `supabase_three_numbers.sql` も先に適用してください。
列追加はNULL許容で、過去の回答を変更せず、テーブルのアクセス権限も変えません。
新規環境は `supabase_setup.sql` に列定義を含みます。カードの保存とJSONバックアップは同じ項目を保持します。

実装は `flashcards.py`（生成・音声文字の数値変換・集計）、`flashcards_ui.py`（画面・進行・保存）、
`flashcard_keyboard/index.html`（端末上の入力・音声認識）に分けています。

### 3つの数の文章題

算数の「もんだいを えらぶ・せってい」→「もんだいの かたち」で「3つの かずの ぶんしょうだい」を選びます。
「2回増える」「2回減る」「増えて減る」「減って増える」の4種類です。
たし算は2回増える問題、ひき算は2回減る問題、ミックスは4種類を偏らせず、重複なく出題します。
たとえば「りんごが3こ。2こもらい、そのあと1こ食べた」という本文から、`3 + 2 − 1` を作ります。
物の数と増減の数は1以上、途中と最後の答えは0〜選択範囲内です。答え0も扱い、負の数は出しません。
10/20まで、5/10/20問、繰り上がり・繰り下がり条件、学校で習った範囲を利用できます。

本文を読み、1回目と2回目の「たす／ひく」を選んでから、文章の順番で3つの数を入力し、最後に答えを入力します。
「しきを なおす」で2つの演算と3つの数を修正できます。段階ヒントは手順→演算と数量の順序→途中の答えと次の式です。
既存のわからない、中断・再開、結果、間違い問題の再練習、類題、おまかせ難易度、きょうの復習に対応します。
中断時は3つの入力と2つの演算・ヒント段階を保持します。本文とヒントは学年別表示にも対応します。

記録では、2回の演算が両方正しいか、3つの数が文章の順番どおりか、自分で作った式を正しく計算したかを分けます。
3項目がすべて正しい場合に全体正解とし、自作した式全体を履歴に残します。
誤った演算で途中または最後が負数になる場合は、計算結果を未評価にします。「わからない」は3項目とも未評価です。
学習レポートと共通レポートでは「3つの数の文章題」を独立集計し、従来の文章題と3つの数の計算の初回成績へ混ぜません。
初回・再練習・最新回答・復習を分け、4種類と繰り上がり／繰り下がり別の傾向も確認できます。

形式は `three_word_problem`、IDは `three_word_v1_種類_範囲_第1数_第2数_第3数` です。
通常練習と復習は同じIDの最新履歴から予定を算出し、自力正解で3日後→7日後、誤答・ヒント使用で翌日に戻します。
同日に何段階も進めず、選択学習者の履歴だけを使い、未来の回答を除外します。
保護者テストでは回答・復習予定・設定・スタンプを永続保存しません。保存再試行は同じ回答IDを使用します。

`third_operand` と `second_operation` は3つの数の計算と共用します。新しい列は追加しません。
バックアップと復元は本文・自作式・3種類の評価も保持し、4種類の演算・ID・範囲を検証します。
公開時は未適用の `supabase_math_visuals.sql` → `supabase_three_numbers.sql` → `supabase_flashcards.sql` →
最新の `supabase_history_restore.sql` → アプリ更新・再起動の順です。

### 3つの数の計算

算数の「もんだいを えらぶ・せってい」→「もんだいの かたち」で「3つの かず」を選びます。
たし算は `2 + 3 + 4`、ひき算は `9 − 2 − 3`、ミックスはこれらと
`5 + 4 − 2`・`9 − 3 + 2` の4パターンを練習します。左から順に計算します。
3つの数・途中の答え・最後の答えをすべて10/20までに収め、負の数は出しません。
0を含む問題も扱います。5/10/20問、繰り上がり・繰り下がり、おまかせ難易度、学校範囲を利用できます。
通常のミックスは4パターンを偏らせず、同じ問題を重複させません。

3段階ヒントは左から考える手順、最初の式、途中の答えと最後の計算を順に表示します。
回答後の解説では2段階の式と正しい答えを確認できます。図は最初の数・2回の増減・最後の数の4行で、
回答前には最後の数の個数を表示しません。図を使った回答は従来どおりヒントありとして記録します。
既存の回答、わからない、中断・再開、結果、間違い問題の再練習、類題、きょうの復習を利用します。
保護者テストでは回答・復習予定・設定・スタンプを永続保存しません。

学習レポート・共通レポート・履歴に「3つの数」を追加し、従来の計算・穴埋め・文章題と分けて集計します。
初回・再練習・各問題の最新回答・復習を分け、4パターンと繰り上がり／繰り下がり別に傾向を確認します。
通常と復習は同じ `three_numbers_v1_*` IDの最新履歴を使います。旧教材IDや国語chain_idは変更しません。
自力正解3日後→7日後、誤答・ヒント使用で翌日の復習に戻り、同日中に何段階も進めません。

`operation` は第1演算、`second_operation` は第2演算、左右の数と `third_operand` は原式の3つの数、
`correct_answer` は左から計算した最終値です。carry/borrowingは該当する演算があるとき両段階のOR、
存在しない演算の属性はNULLです。「あり」はどちらかの段階に繰り上がり／繰り下がりがある問題、
「なし」は両段階ともない問題を選びます。通常の2数問題では追加2項目はNULLです。
SQLiteは起動時にnullable2列を追加して旧履歴を保持し、旧JSONもNULLとして取り込みます。
クラウド公開時は `supabase_math_visuals.sql`（未適用の場合）→ `supabase_three_numbers.sql` → `supabase_flashcards.sql` →
更新版 `supabase_history_restore.sql` → アプリ更新・再起動の順です。新規プロジェクトは更新版setupと復元SQLを使用します。
SQLは列と復元関数の追加更新だけで、既存回答を削除・上書きしません。

### □に入る数・図で考える算数

算数の「もんだいを えらぶ・せってい」→「もんだいの かたち」で「□の かず」を選びます。
`□ + 3 = 8`、`5 + □ = 8`、`□ − 3 = 5`、`8 − □ = 5` の4種類を練習できます。
10/20まで、5/10/20問、たし算・ひき算・ミックス、繰り上がり・繰り下がり条件を利用します。
通常セットは左右の□と演算の偏りを抑えて重複なく出題します。ヒント、わからない、
中断・再開、結果、間違い問題の再練習、おまかせ難易度、学校範囲、類題、毎日の復習にも対応します。

「図で かんがえる」をONにすると、計算・3つの数・穴埋めを丸で表示します。OFFでも問題中に「ずを みる」で開けます。
丸1つは1個、10個ずつの枠で数のまとまりを確認します。ひき算の「とる数」は線を付けた丸です。
未知の数は個数・長さを示さない同じ大きさの□で表示し、回答後に正しい数を確認できます。0も表示します。
文章題では演算選択の手がかりを先に示さないため、この図は表示しません。
図のON/OFFはこのブラウザーの一時設定で、再練習や設定画面へ戻っても保持します。
ページの再読み込み・保護者テストの開始/終了でリセットします。

回答前の図の使用を `visual_help_used` として記録し、ヒントありの正解に含めます。
文字ヒントの段階 `hint_level` は別に0〜3で保持するので、図だけなら段階0・ヒントありです。
図を使った正解の復習は翌日、自力で正解したら従来どおり3日後→7日後。誤答・補助使用で翌日に戻します。
同日中の繰り返しで間隔を何段階も進めません。回答後に開いた図は補助使用に数えません。
履歴・教科別レポート・共通レポートで穴埋めと図の使用を確認できます。
穴埋めは初回・再回答・最新結果・復習を分け、従来の計算と文章題の成績へ混ぜません。
保護者テストでは回答・図の使用・復習予定・設定・スタンプを保存せず、終了時に図の一時設定も破棄します。

穴埋めのIDは `fill_blank_v1_*`。左右の□はそれぞれ別IDで、既存の計算・文章題・国語chain_idは変更しません。
`operation` と左右の数は隠す前の式、`correct_answer` は□に入る数です。
繰り上がり・繰り下がり・10をまたぐ属性は元の式で判定し、`answer_is_10` は□に入る数が10かを示します。
予定は同じ教材IDの最新履歴から算出するので、通常練習と復習のどちらも次の予定に反映します。
学習者ごとに分離し、未来の回答は復習・おまかせ・穴埋め集計から除きます。

SQLiteは起動時に図の使用列を追加します。Supabaseへの公開時には、既存の保存先で
`supabase_math_visuals.sql` → `supabase_three_numbers.sql` → `supabase_flashcards.sql` → 最新の `supabase_history_restore.sql` の順に実行してからアプリを反映します。
新規プロジェクトは更新版 `supabase_setup.sql` を使用し、その後に復元SQLを実行します。
SQLは列と既存の復元関数を追加更新するだけで、回答を削除・上書きしません。
旧JSONは図の使用・第三の数・第二演算をNULLとして取り込み、穴埋め・図の使用・3つの数も同じJSON形式で復元できます。
誤入力で保存した3桁の回答（0〜999）もバックアップ可能です。正しい答えの10/20までという制約は維持します。

### 追加の文章題・理由と気持ちの読解

追加教材とJSON復元を実装しました（2026-10-08）。

算数の「文章題」に、最初の数・増えた数・減った数を求める4種類を追加しました。
たとえば「2こもらって8こになった。はじめは？」は `8 − 2`、
「2こ食べて3こ残った。はじめは？」は `3 + 2` で考えます。
出来事の言葉だけで演算を決めず、問われている数を見つける練習です。
従来と同じ「たす・ひくを選ぶ→式に使う数を入れる→答える」の順に進み、
3段階ヒントと回答後の正しい式を利用できます。
本文の数と答えは選択した10/20までの範囲を守ります。繰り上がり・繰り下がり条件は解く式に適用します。
学校範囲・おまかせ難易度・復習にも新教材が入ります。新しいIDは `word_v2_*`、既存6種類は `word_v1_*` のままです。

国語の「みじかい おはなし」に理由8問・気持ち8問を追加し、教材は全136問になりました。
本文に書かれた理由、2つの文をつないで考える理由、行動・言葉・気持ちの変化を読みます。
答えた後の解説には、手がかりになる本文の正確な引用と文番号を表示します。
難易度1/2/3の教材があり、おまかせ難易度・復習・分析・間違い問題の再練習に対応します。
新しいIDは `jp_reading_v1_001`〜`016`。既存120問の内容・IDと過去の成績は保持します。
どちらの教材も既存の保存形式を利用するため、教材追加だけならSQL変更は不要です。

### 学習記録のバックアップと復元

両教科の「おうちの人へ・レポートと設定」→「週間レポート・学習目標・記録の書き出し」→
「目標・記録の保存」で「学習記録のバックアップ・復元」を開きます。
JSONを端末へ保存し、必要なときに同じ学習者を選んでそのファイルを読み込みます。
復元先と新しく追加する算数・国語の件数を確認してチェックし、「確認した履歴を復元する」を押してください。
CSVは表計算用の書き出しで、復元にはJSONを使います。

バックアップには選択中の学習者の保存済み全回答を含めます。通常・再練習・復習、ヒント、読み方確認、
国語のchain_idと旧review_due_at、回答時刻・回答IDを保持します。
漢字表示・学習目標・学校範囲などの設定、問題報告、未保存の回答、保護者テストの回答は含みません。
作成時点以降の回答は新しいバックアップで保存してください。個人の学習記録なので家庭内で保管します。
ファイルは10MB・両教科合計20000件までで、形式バージョンとチェックサムを検証します。

復元は新しい回答IDの追加だけです。同じID・同じ内容は追加せず、同じIDで異なる内容がある場合は
両教科とも復元を取り消します。別の学習者への復元はできません。
既存の回答を削除・上書きせず、復習・分析・難易度・スタンプは保存された履歴から再計算します。
応答が失われた場合も同じファイルで再試行でき、記録を二重に追加しません。
保護者テストでは「保存せずに復元を確認」で形式・件数だけを確認し、通常の履歴と復習予定を変更しません。
テスト終了時にはファイル選択・確認チェック・確認結果を破棄します。

ローカルは既存の算数・国語SQLiteをATTACHして一括トランザクションで復元します。
両DBはファイル保存とDELETEジャーナルを必要とし、WALなどの場合は書き込まずに止めます。
クラウドは `supabase_history_restore.sql` の `restore_answer_history` RPCを利用し、両教科を一括で復元します。
公開前に既存の履歴テーブルと段階ヒントの追加SQLが適用済みであることを確認し、追加SQLを実行してください。
RPCはservice_roleだけが実行でき、匿名・一般ログイン利用者への権限やUPDATE/DELETE権限は増やしません。
クラウドの失敗時にローカルへ保存先を切り替えません。

### やさしいカード画面

名前を選ぶと、上部の算数・国語カードで教科を切り替えられます。
先頭の緑の「きょうの ふくしゅう」カードから最大5問を始めます。
通常練習は算数が淡青、国語が淡桃のカードです。「もんだいを えらぶ・せってい」を開くと
これまでの出題条件を変更できます。閉じていても現在の設定で開始します。
類題・復習予定は「もっと れんしゅう」、履歴・ごほうびは「がんばりの きろく」、
週間・共通レポートと漢字設定は画面下の「おうちの人へ・レポートと設定」から開きます。
問題画面も同じ色と丸角で統一し、タッチ操作とキーボード操作を引き続き使えます。
この表示変更には追加SQLは不要です。履歴・問題ID・復習間隔・保護者テストの保存ルールは同じです。

### 保護者のテスト（記録しない）

名前を選ぶ前に「保護者の操作確認」を開き、「保護者のテストを始める（記録しない）」を押します。
上部の「保護者のテスト中」が目印です。算数・国語の回答、再練習、ヒント使用、読み方確認は
このブラウザ内だけで扱い、SQLite・Supabaseの学習履歴には書き込みません。分析やスタンプも増えません。
漢字・読み方設定は「保存せずに試す」で一時表示を確認できます。履歴・レポートは通常学習の記録を表示します。
「テストを終了して通常の学習に戻る」で途中のテスト回答と仮設定を破棄し、名前選択に戻ります。
モード切替時は途中のセットを終了します。お子さまへ渡す前にテストを終了してください。
ページ再読み込み・新しいブラウザセッションでは通常モードになります。テスト状態は別端末へ共有しません。
保存済みの過去記録は変更・削除しません。データベースの追加SQLは不要です。

### おまかせ難易度

算数・国語の通常練習カードの「おまかせで れんしゅう」から開始します。
既存の問題数・分野・数の範囲・演算・形式・繰り上がり条件を守り、次のセットの難しさを調整します。
手動条件でランダムに練習したい場合は、従来の「れんしゅう スタート」「こくご スタート」を使えます。

`adaptive_difficulty.py` は選択中の学習者の保存済み通常初回回答だけを使い、日時指定で検証できます。
未来・不正日時・回答IDの再送・復習・再練習・苦手練習・保護者テストは判定対象外です。
算数は演算・数の範囲・形式・繰り上がり条件ごと、国語は分野ごとに、基本の段階から履歴を再生します。
算数10までは最大の数が3以下／6以下／それ以外、20までは10以下／10超の繰り上がりなし／繰り上がりあり
（ひき算は繰り下がり）を教材内の3段階とします。国語は既存の `difficulty` を使います。
てにをはで手動レベルを指定した場合は、そのレベル内だけで選びます。
現行の国語教材は難易度1だけの分野もあり、それらは難しい新規問題へ自動拡張しません。

現在段階の通常初回回答を原則5問集め、自力正解8割以上なら一段階上げます。
誤答・わからないが4割以上、またはヒント使用が6割以上なら一段階下げます。それ以外は維持します。
候補が3〜4問だけの段階はその数で判定し、2問以下では変更しません。
少量のミックス練習でも、未判定の回答は日をまたいで積み上げます。
日本時間の同一日に同じ問題を解き直した場合は、その日の最初の通常回答だけを使います。
必要件数が最初に揃った時点でその日の判定を固定し、同日後続の回答で進めたり覆したりしません。
判定に使った回答は消費し、同じ古い証拠を翌日以降に繰り返し使いません。
ヒントが未記録の古い正解は、自力正解と推測しません。読み方確認は解法ヒントと区別します。

セット中・中断再開・保存の再試行では、開始時の選定と理由を保持します。
分野おまかせの国語は偏りを抑えて出題します。同じ段階では未回答問題を優先し、
候補不足は近い段階の問題で補います。問題の重複はなく、全体が不足する場合は用意できる数と理由を表示します。
問題・結果画面の「保護者向け：おまかせ難易度の理由」で、分野ごとの判断を確認できます。

回答は通常練習の `normal` として既存の初回集計・保存・復習予定に結びます。
問題ID・国語chain_id・保存再試行の意味は変えません。難易度の進度を別途永続保存せず、履歴から導出するため
回答IDの再送で進度は増えません。保護者テストでは通常履歴を参考に表示を試せますが、テスト回答では進度を変更しません。
追加SQL・DB変更は不要です。公開する場合は新規モジュールと `app.py` / `japanese_ui.py` を一緒に反映します。

### きょうの ふくしゅう

学校範囲を指定した教科では、今の単元の候補と本人が以前回答した現行教材IDを復習対象にします。
今の範囲が狭くなっても、過去に学習した範囲の復習を保持します。予定表示にも同じ候補を使います。
未指定の場合は従来どおり、算数は練習画面の数の範囲、国語は助詞レベルの制限を使います。

算数・国語それぞれの設定画面の「きょうの ふくしゅう」から、選択中の学習者の復習を最大5問始めます。
通常の問題数や出題モードを選び直す必要はありません。既存の回答・ヒント・中断と再開・結果・
間違い問題の再練習を使えます。保護者向けの折りたたみに出題理由を表示します。

選定と復習日の計算は画面から独立した `daily_review.py` にあり、日時を指定して検証できます。
全ページの履歴を取得し、選択中の学習者・教科の有効な回答だけを使います。日本時間を基準とし、
現在より未来の回答を除外します。同じ回答IDの再送も1回答として扱います。

1. 復習日を迎えた、最新回答が誤答の問題。
2. 復習日を迎えた、最新回答がヒント付き正解の問題。
3. 復習日を迎えた、最新回答が正解済みの問題。
4. 未回答の苦手分野の問題。不足分は未回答の基本問題で補います。

同じ優先度では古い復習日を先にします。最新回答で解決状態を判定するので、過去の誤答が
後の正解で解決した場合は未解決の誤答として扱いません。期限前の問題を補充に回しません。
苦手分野は通常の初回回答が5問以上で正答率80%未満、または記録済みヒント使用率30%以上を目安にします。
算数は現在選んだ数の範囲（10まで／20まで）と一致する問題IDを使い、計算・3つの数・穴埋め・文章題・3つの数の文章題から選びます。
演算・繰り上がり条件・問題の形は通常練習の設定であり、復習では履歴を優先します。
国語は現行教材の全分野から選び、設定中のてにをはレベルより難しい助詞問題を除外します。
未回答の補充は既存の難易度が低い問題を先にします。問題IDは変更しません。
重複なしで5問に満たない場合は用意できる数、0問なら理由を表示して開始しません。
履歴の読み込みに失敗した場合も開始せず、同じボタンで再試行できます。

復習間隔は、通常・再練習・復習を同じ教材IDで結び、保存済み回答から毎回算出します。
日本時間の学習日ごとに判定し、その日に誤答・ヒント使用が一度でもあれば翌日へ戻します。
ヒントなしの正解だけの日は初回3日後、次の異なる学習日でも自力正解なら7日後、以後7日後です。
同日に何度正解しても一段階まで。最後に正解しても同日の誤答・ヒントによる翌日設定は保持します。
ヒントが未記録の古い正解は自力正解と推測せず、段階を進めません。
期限は日本時間の日付単位（当日0時から対象）で、別の予定表への書き込みはありません。

記録の `selection_type` は復習開始が `review`、復習内の間違い問題の再練習が `review_retry` です。
両方とも通常の初回正答率・苦手分析・通常の再練習成果から除外し、履歴と復習の成果欄で別表示します。
算数の通常・再練習レポートは従来どおり最新500回答、復習は別枠の最新500回答を集計します。
復習回答が増えても通常評価の対象を押し出しません。共通レポートの学習量には復習も含みます。
国語は復習セットごとに新しい `chain_id` を作り、そのセット内の再練習だけ同じchainを引き継ぎます。
長期予定は `chain_id` ではなく `question_id` で結びます。従来の `review_due_at` は誤答時だけの
旧予定として保持し、今回の復習選定には使いません。古い履歴を変更する必要はありません。

保存失敗時は既存の未保存回答・同じ `attempt_id` を再送します。重複保存を防ぎ、予定を余分に進めません。
保護者テストの復習もブラウザ内だけで、回答・復習予定・表示設定・スタンプを永続保存しません。
通常モードの算数で復習セットを完了した場合は、既存と同じ1セット1スタンプです。

追加SQL・DB変更は不要です（算数の `selection_type` はTEXT、国語はJSON payload）。
公開時は検証済みの新規モジュールと変更ファイルを一緒に反映してください。

### 学校で習っている範囲

各教科の設定画面下の「おうちの人へ・レポートと設定」から「学校で習っている範囲（保護者向け）」を開きます。
子どもごとに算数の単元と国語の分野を保存し、次の「おまかせで れんしゅう」から自動で使います。
算数は10まで／20までのたし算・ひき算、くり上がり／くり下がりあり・なし、両演算から選べます。
国語は既存の各分野・全分野・てにをはレベル1〜3までです。教科書固有の進度や新しい教材を追加する機能ではありません。
「指定しない」は、毎回の練習画面の設定を使う状態に戻します。
問題数と算数の計算／文章題は練習画面の設定を守り、手動スタートは従来の条件のままです。
国語の学校設定のてにをはレベルは上限で、その範囲内で難易度を調整します。従来の手動レベルの完全一致とは区別します。

設定は専用の `family_school_scope` に保存し、成績・学年表示・学習目標を変更しません。
初期値の読み取りだけではSQLiteファイルを作りません。クラウド設定済みのときは必ずSupabaseを使い、
設定の読み込みに失敗するとおまかせ・復習を停止して再試行を案内します。手動練習は引き続き使えます。
設定保存の応答が失われた場合は入力を保持し、同じ子ども・同じ内容のupsertで再試行します。
保護者テストでは「保存せずに範囲を試す」を使い、別の仮設定をブラウザ内だけで適用します。
テスト終了・開始・再読み込みで仮設定を破棄し、通常設定へ戻ります。学習回答・予定・スタンプは保存しません。

学校範囲を指定した教科の復習は、現在の単元に加え、本人が過去に解いた現行教材の問題も含めます。
他の子ども・未来の記録・存在しない教材IDは対象外です。過去の本文を問題として復元せず、現行教材からIDで再生成します。
未知の過去単元の問題を新たに補充しません。最新回答・復習間隔・初回との別集計・教科ごとの1日5問上限は同じです。
学校範囲変更後も、開始済みの練習と中断再開は元のセットを維持します。

既存Supabaseでは `supabase_school_scope.sql` 全体をSQL Editorで実行してから、関連ファイルを公開してください。
専用テーブルを追加するだけで、既存履歴の削除・移行は不要です。RLS有効、anon/authenticatedの直接アクセス禁止、
service_roleにはselect/insert/updateのみを付与します。新規用 `supabase_setup.sql` にも同じ定義を含めています。
ローカルSQLiteは最初の設定保存時にテーブルを追加します。
2026-10-08に学校範囲とおまかせ難易度を公開し、既存Supabaseへ追加SQLを適用しました。

### 週間レポート・学習目標・復習予定

両教科の設定・結果・レポートから「週間レポート・学習目標・記録の書き出し（保護者向け）」を開きます。
日本時間の今日を含む7日と、その前7日を比較します。初回の集計は既存レポートと同じ基準です。
算数は通常練習、国語は回答回数1の通常・苦手練習。復習と復習の再練習は別枠で表示します。
学習した日、初回正答率、ヒント使用率と段階、復習成果を確認できます。
同じ教材の直前の状態が誤答・ヒント使用から自力正解へ変わったとき、できるようになった問題を表示します。
問題や難易度・回答数が違うため、前週との差だけで成長や能力を断定しません。

目標は子どもごとに週1〜7日・1日1〜20問、初期値は週3日・1日5問です。正答数ではなく取り組みを評価します。
両教科の通常・類題・復習の回答を合計し、同じセットの再練習は目標問題数に含めません。
保護者テストでは目標を保存せずに試せます。終了すると仮の値を破棄します。
保存に失敗した場合は値を保持し、同じ内容で再試行できます。

各教科の設定画面の「復習の予定をみる」でも、今日と明日新しく期限を迎える問題数を確認できます。
現在の数の範囲・助詞レベルに合う保存済み問題を数え、取り組む目安を各教科最大5問にします。
期限を迎える問題が6問以上でも、各教科の復習は日本時間で1日5回答まで。残りは以降の復習へ回せます。
同日に2問復習済みなら次のセットは最大3問、5問復習済みなら翌日の案内を表示します。
数の範囲を変えても同じ教科の上限を引き継ぎます。復習内の間違い問題の再練習は追加の枠を消費しません。
基本問題の補充は予告の件数に含めません。明日の件数は今日の回答によって変わります。

### 段階ヒント・わからない・類題

両教科のヒントは「考えるきっかけ→具体的な見方→解き方の手順」の3段階です。
必要なときだけ次のヒントを開き、使用した最大段階を回答と一緒に保存します。
中断と再開でも段階を保ち、次の問題・再練習では新しく考えます。回答前に正解自体は示しません。
以前の段階未記録の履歴は、ヒントの有無だけを使い、段階を推定しません。

「わからない」は空欄や当てずっぽうの回答と区別して保存します。
正答率では未正解、翌日以降の復習対象となりますが、式の選択ミスや助詞の混同としては扱いません。
答えはNULL、国語の表示は「わからない」です。セット終了後は既存の再練習で取り組めます。
保護者テストではヒント段階・わからないも保存しません。

設定画面の「にた もんだいで れんしゅう」は、最新の誤答・ヒント使用・苦手分野を手がかりに最大5問出します。
現行教材の問題IDを使い、元問題に近い数・文章の意味関係・国語分野や問い方の別問題を優先します。
同じセットに重複はなく、未回答の候補を既回答より先にします。履歴がない場合は基本の問題を用意します。
算数は選択中の数の範囲、国語は設定中の助詞レベル上限を尊重します。
記録は既存の `weak_area` で保存。算数の通常初回率とは別枠、国語は既存の苦手練習の初回基準を維持します。

### 間違い方・問題報告・CSV保存

保護者画面の「つまずき・復習予定」で、算数の計算、文章題の演算選択・式の数と順序・自分の式の計算を分けます。
国語は分野・教材の誤答分類・実際に選んだ助詞の混同を表示します。記録がない項目は未評価です。
「わからない」は別件数で表示し、読み違いなどの原因を推測で決めつけません。
通常初回の記録を対象とし、復習を足して苦手評価を変えません。

問題画面の「保護者向け：問題について報告」から「難しすぎる・読みづらい・答えがおかしい」を残せます。
教科・学習者・問題ID・日時を含むアプリ内の確認記録です。メールなどで外部へ自動送信しません。
一つの報告を保存し直すときは同じIDを送り、応答が失われても二重登録しません。
テスト中は報告も保存しません。保護者画面から選択中の学習者の報告を確認できます。

「両教科の履歴をCSVで保存」で、選択中の学習者の保存済み全履歴をダウンロードできます。
日本時間の有効な回答だけを含み、未来の記録・別の学習者・再送重複を除外します。
復習・再練習・ヒント・わからない・chainを含む全保存項目を列に保持します。
UTF-8 BOMでExcelでも開きやすくし、文字列の数式実行を防ぐため危険な先頭文字に引用符を付けます。
CSVの読み込み・復元機能はありません。保護者テストの未保存回答は書き出しにも含みません。

追加SQLは既存SupabaseのSQL Editorで `supabase_learning_extensions.sql` 全体を実行します。
算数の `hint_level` と、共通の `family_learning_settings` / `problem_feedback` を追加するだけです。
国語は既存JSON payloadを使います。RLSを有効にし、公開鍵・ユーザー認証の直接アクセスを禁止します。
新規プロジェクト用 `supabase_setup.sql` には同じ追加定義を含みます。SQLiteは必要な列を追加し、既存回答を変更しません。

### 通常の学習

1. なまえのボタンを押し、「もんだいを えらぶ・せってい」で学習モード、数の範囲、問題数（5・10・20問）、繰り上がり・繰り下がり、問題の形（けいさん／ぶんしょうだい）を選びます。
2. 数字キー・テンキーで答えを入力し、Enterで回答します。Backspaceで修正できます。
3. 正誤表示後、Enterまたはボタンで次に進みます。
4. 終了画面で正答数・正答率を確認し、間違えた問題だけ再練習できます。
5. 設定・練習・終了画面の「学習履歴」から、選んだ名前の保存済み回答を確認できます。
   日本時間の日時、問題、自分の回答、正しい答え、正誤、初回／再練習、出題順、回答回数、回答時間を
   新しい順に50件ずつ表示します。「もどる」で元の画面に戻ります。
   問題枠の「学習履歴」から移動しても、問題の進行・入力途中の内容・ヒント状態を保持します。

### もどる・入力・ヒント

問題枠の「もどる」は設定画面へ一時中断します。「つづきから」で同じ問題を再開できます。
算数の入力途中の式・答え、国語の並べ替え途中の順番、ヒント使用と回答時間を引き継ぎます。
設定画面で過ごした時間は回答時間に含めません。保存済み回答を上書きしたり、再開時にもう一度保存したりしません。
別の学習者には「つづきから」を表示しません。新しく練習を始めると途中のセットを置き換えます。
保存に失敗した回答は、保存をやりなおしてから戻れます。

入力画面は最初から数字入力欄にフォーカスします。演算や国語の選択式は最初のボタンにフォーカスし、
そのまま数字・Tab・Enterで操作できます。iPhoneのソフトキーボードが開くかどうかは端末の制限に従います。
回答前の「ヒントを みる」は考え方を表示し、答え自体は示しません。
算数は回答後の「かんがえかた」で正しい式・答え・解き方を確認できます。国語は回答後に解説を表示します。
回答前にヒントを開くと `hint_used=true` をその回答に保存します。回答後の解説はヒント使用扱いにしません。

入力欄は問題表示時に自動でフォーカスされます。別の場所をクリックしてから
キー操作する場合は、答えの欄または次へボタンをクリックしてください。
空欄は回答として記録しません。数字以外は入力欄から除き、全角数字は半角に変換します。
不正解時には答えを表示せず、セット終了後にもう一度解きます。

## 履歴とデータの意味

### 文章題

短いひらがなの本文を読み、「たす ＋」「ひく −」を選んでから数値を回答します。
選ぶ前は数式・数字入力欄を表示しません。選択ボタンはTabで移動しEnterで決定できます。
選択後に自分で左右の数を入力して式を作り、その式の答えを入力します。
式の入力と答えは数字・テンキー・Tab・Enter操作に対応し、「しきを なおす」で修正できます。
演算選択・式の数と順序・計算結果を合わせて1回答レコードに保存し、3つとも正しい場合だけ全体正解にします。
間違えた演算を選んでも回答でき、再練習では演算をもう一度選びます。
回答時間は本文表示から演算選択を経て数字を確定するまでです。
履歴・設定画面への移動時には経過時間を保持し、練習を再開してから計測を続けます。

既存6種類は増える（increase）、減る（decrease）、合わせる（combine）、全体から部分を分ける（separate）、
多さを比べる（compare）、足りない数を求める（difference）です。
これらは結果（result）または差（difference）を求めます。追加4種類は初めの数（start）・増減の数（change）を求めます。
物の数は1以上で、全部食べる・椅子がちょうど足りる場合の答え0は出題できます。
既存は `word_v1_種類_範囲_左右の数`、追加は `word_v2_種類_範囲_左右の数` を安定したIDとして使います。
左右の数は正しい計算式の順であり、本文に登場する順とは異なる場合があります。表示した本文も保存します。

`operation_selection_correct` は演算選択の正誤、`calculation_correct` は選んだ式の計算の正誤です。
例：正しい式が3＋2の問題で「ひく」を選び1と答えると、演算は不正解、選んだ3−2の計算は正解、全体は不正解です。
負数は入力できないため、誤選択の式が負の数になる場合は計算を未評価（NULL）にします。
`equation_correct` は文章から使う数と順序の正誤です。2つの数のたし算は左右の交換を認め、ひき算は正しい順序が必要です。
3つの数の文章題は3数量を本文の順序どおりに使います。演算選択は2回とも正しい場合に正解とします。
演算の正誤は別に評価するため、正しい数を使って演算だけ間違えた場合は式の数と順序は正解になります。
`user_equation` に自作式を保存します。更新前の回答は式の記録・評価ともNULLのままです。
履歴表には自分の式と3種類の評価を表示します。文章理解そのものを点数化する機能はありません。

### 国語との統合

同じ家族用パスワード・学習者選択から、設定画面上部の「さんすう」「こくご」で切り替えます。
国語はことば、1文読解、だれ・なに・どこ、文の順番、短文読解、穴埋めの6分野・80問に加え、
助詞「てにをは」のレベル1〜3・40問、理由と気持ちの追加読解16問を用意しています。
選択問題は数字キーやタッチで回答し、文の順番は選んだ順に並べます。
国語の履歴・苦手分析・再練習は国語画面から開きます。
科目ごとの練習状態と履歴を分け、国語は `public.japanese_attempts`（ローカルでは `data/japanese.sqlite3`）へ保存します。
既存の算数履歴・ユーザーID・家族用パスワードを引き継ぎます。国語は外部AIを使わずに集計します。

### 共通レポート・教科横断分析

算数・国語の設定画面、各教科の分析・結果画面にある
「共通レポート・教科横断分析（保護者向け）」から開きます。
最近7日・最近30日・全期間を選べます。日付は日本時間の当日を含み、未来の回答は集計しません。
両教科の全ページを取得し、同じ学習者・期間で回答数、学習日数、初回・再練習の正答率、日別学習量を表示します。
両教科の学習日が重なる日は、全体の学習日数では1日と数えます。

算数の初回は通常練習、国語の初回は回答回数1（苦手練習を含む、再練習を除く）です。
教科間で正答率を合算した能力点や順位は作りません。
計算問題、文章題の全体正解・演算選択・数と順序・選んだ式の計算、国語の自力読みの読解を並べます。
国語読解の対象は1文読解・情報抽出・短文読解です。
文章題の未評価項目は分母から除き、各段階の回答数は合算しません。
5問未満は判断保留、5問以上で80%未満の項目は確認したい練習を提案します。
この目安は共通レポートの練習提案用で、教科別の既存評価を置き換えません。
誤答原因や教科間の因果関係は断定しません。回答時間で教科を比較する評価も行いません。

戻る操作では各教科の進行状態を保持します。練習設定へ移動しても新しいセットは自動開始しません。
片方の履歴を読み込めない場合はエラーと再試行を表示し、部分的なレポートを完成扱いにしません。
既存のSQLite・Supabaseテーブルと認証を使うため、追加SQL・外部AIキーは不要です。

全体構成は `app.py` が認証・学習者・画面遷移を担当し、教科固有の出題・保存・評価を
`learning.py` / `assessment.py` と `japanese.py` / `japanese_ui.py` に分けています。
`cross_subject.py` は保存レコードを変更せず両教科を読み取り集計し、
`cross_subject_ui.py` は共通レポートの表示を担当します。

### 学習カレンダーとごほうび

設定・終了・学習履歴画面の「学習カレンダー・ごほうび」から開き、年と月を選びます。
月曜始まりの暦に学習した日の✅とスタンプ獲得日の⭐を表示します。
日別表では、回答数・正答率、初回回答・再練習それぞれの件数と正答率を確認できます。
日時は日本時間で集計します。対象月をUTCの開始・終了日時で絞り込み、全ページを取得するため、500回答を超えても省略しません。

1セットの最後の回答が保存できたとき、正誤にかかわらずスタンプを1個獲得します。
通常練習と再練習の両方が対象です。途中のセットや最後の回答が未保存のセットには付きません。
`round_size` はセットの問題数、`round_completed` は最後の回答の完了フラグです。
最終回答と同じレコードで保存するため、再送や画面の開き直しでスタンプが増えることはありません。
更新前の履歴はこの2項目がNULLで、スタンプ対象外です。
SQLiteは起動時に列を追加します。Supabaseは公開コード更新前に `supabase_attempts.sql` を再実行してください。

繰り上がり・繰り下がりは「おまかせ／なし／あり」で選びます。ミックスではたし算とひき算にそれぞれの条件を適用します。
同じセットに問題を重複させず、条件に合う問題が不足する場合は理由を表示して開始ボタンを無効にします。
例えば10までの繰り上がりありのたし算は9問、繰り下がりありのひき算（10−1〜10−9）も9問なので、各5問は開始できますが10・20問は開始できません。

### 学習レポート

設定・終了・学習履歴画面の「学習レポート」から開きます。
選択した学習者の通常・再練習の最新500回答までをSQLiteまたはSupabaseから集計します。
復習は別枠の最新500回答までを集計します。
計算問題と文章題は混ぜません。計算問題の習熟評価とおすすめ練習は計算問題の初回回答だけを使います。
文章題は初回・再練習それぞれで全体正答率、演算選択の正答率、選択した式の計算正答率と評価件数を別表示します。
対象の回答数と日付範囲を画面に表示し、初回回答と再練習を分けます。
外部AIを呼び出さない、集計と明示的な基準による評価なので、AIのAPIキーや利用料は不要です。

- 初回正答率と、正解した初回回答の回答時間の中央値を表示します。
  回答時間は休憩や操作の影響もあるため、苦手判定には使いません。
- 演算・数の範囲・繰り上がり／繰り下がりの有無で問題を分類します。
  5問未満は判断保留、90%以上は「よくできています」、80%以上90%未満は
  「もう少し練習」、80%未満は「優先して練習」です。学力の診断ではありません。
- 同じ分類に20問以上あると、直近10問とその前10問の正答率を比較します。
- 優先課題がある場合は、正答率が最も低い分類の5問をボタンから始められます。
  優先課題がない場合は、学習済みの最大の数の範囲でミックス10問を提案します。
  未学習の場合は10までです。おすすめ問題は新しい通常セットとして保存します。
- レポートを開いて戻る操作では進行中の練習を保持します。
  おすすめ練習を開始すると新しいセットに切り替わります。

### 保存方法

SQLiteの `attempts` テーブルへ回答ごとにコミットし、既存の回答を上書きしません。
保存に失敗した場合は次へ進まず、確定した回答を表示します。
「ほぞんを やりなおす」ボタンで、同じ回答・日時・回答時間のレコードを再保存できます。
同じ `attempt_id` の通信再送は重複保存しません。

- `session_id`：通常5・10・20問（レポートのおすすめは5問）、または再練習1回のセットID。再練習ごとに新しく作ります。
- `question_order`：そのセット内の出題順。再練習も1から始まります。
- `problem_id`：演算・範囲・左右の数からなる問題ID。再練習でも同じIDです。
- `selection_type`：通常は `normal`、再練習は `retry`、類題・苦手練習は `weak_area`。復習は `review`、その再練習は `review_retry` です。
- `attempt_count`：通常セットから連続する再練習における、その問題の回答回数。
  新しい通常セットでは1から始めます。初回正答率は `selection_type=normal` で抽出できます。
- `datetime`：日本時間（UTC+09:00）を含むISO形式の回答日時。
- `response_time_sec`：ブラウザーに入力欄を表示してから確定するまでの時間。
  通信やDB保存の待ち時間は含みません。

全保存項目と型は `learning.py` の `COLUMNS` に定義しています。
SQLiteで真偽値は0/1、未使用属性はNULLとして保存します。
`calculation_correct` は計算問題・3つの数では正しい式の最終結果、穴埋めでは□の数、文章題では選んだ式の計算結果の正誤です。
計算・3つの数・穴埋め問題の `operation_selection_correct`・`equation_correct`・`user_equation` はNULLです。
`blank_position` は計算・3つの数・文章題では `answer`、穴埋めでは `left_operand` または `right_operand`。
`story_type` と `unknown_type` は文章題だけで使用します。
`hint_used` は回答前の文字ヒントまたは図の使用、`hint_level` は文字ヒントの最大段階（0〜3）です。
`visual_help_used` は回答前の図の使用。旧回答のNULLは記録なしで、使用率の分母に入れません。
`dont_know_used` は「わからない」で回答したかを示します。以前の段階未記録の回答はNULLです。

現在使用中の値：

| 項目 | 候補 |
|---|---|
| `selection_type` | `normal`, `retry`, `weak_area`, `review`, `review_retry` |
| `problem_format` | `calculation`, `three_numbers`, `fill_blank`, `word_problem`, `three_word_problem` |
| `blank_position` | `answer`, `left_operand`, `right_operand` |
| `story_type` | `increase`, `decrease`, `combine`, `separate`, `compare`, `difference`, `increase_start`, `increase_change`, `decrease_start`, `decrease_change`, `increase_twice`, `decrease_twice`, `increase_then_decrease`, `decrease_then_increase` |
| `unknown_type` | `result`, `start`, `change`, `difference` |

### 計算属性のルール

以下は従来の2数のルールです。3つの数では両段階を確認し、繰り上がり・繰り下がり等の属性を統合します。

- たし算は左右の数と答えが選択範囲内、ひき算は左右の数が範囲内で答えが0以上。
- 0を含む問題も出題します。同じセット内の問題は重複しません。
- ミックス10問はたし算5問・ひき算5問をシャッフルします。
- `carry`：一の位の和が10以上。ひき算ではNULL。
- `borrowing`：引かれる数の一の位が引く数の一の位より小さい。たし算ではNULL。
- `crosses_10`：たし算は両方10未満で答えが10超、ひき算は10超の数から引いて答えが10未満。
  ちょうど10になる計算はfalseで、`answer_is_10` で別に分類します。
- `zero_included`：左右の数のどちらかが0。
- `doubles`：同じ数同士のたし算。
- `near_10`：MVPでは8または9を含み、答えが10超のたし算と定義します。
- `commutative_pair`：左右を小さい順にしたたし算の識別文字列。ひき算ではNULL。

```python
import sqlite3
with sqlite3.connect("data/history.sqlite3") as db:
    rows = db.execute(
```

## 検証

ヒントの使用は回答を確定したときに保存し、履歴に「あり／なし／記録なし」を表示します。
算数・国語・共通レポートでは、初回回答のヒント使用率と、ヒントなし／ありの正答率・回答数を分けて表示します。
ヒントを使った正解も正解です。記録のない過去回答は使用率の分母から除外します。
既知の初回回答が5問以上でヒント使用率30%以上の項目は、手順を振り返る練習の手がかりにします。
回答後の解説表示はヒント使用に数えません。問題の違いもあるため、正答率の差だけでヒントの効果は判断しません。

算数・国語の設定画面から「漢字・読み方設定」を開き、子どもごとに表示学年（小1〜小6）を設定できます。
問題の難しさとは別設定です。学年までの配当漢字を使い、先の学年の漢字や「まだ習っていない漢字」を
含む語は、確認済みの読みでひらがなに戻します。文部科学省の学年別漢字配当表1026字を使用しています。
毎年4月1日の自動進級は任意で、小6まで。開き直し・次の問題から適用し、途中の入力を維持します。
ふりがなは「全部につける／今年習う漢字だけ／なし」。今年の漢字を含む語単位で小さく付けます。
ふりがなのない語はタップして読み方を確認でき、回答時に `reading_help_used` としてヒントとは別に保存します。
履歴と教科別・共通レポートに確認数・率を表示し、読みの確認では正答率を減点しません。
旧履歴に記録がない場合は「記録なし」とし、率の分母から除外します。

確認済みの教材全文を `canonical_text.py` で照合し、`text_display.py` で表示だけを切り替えます。
文字そのものを学ぶ国語問題や助詞の選択肢は元の表記を保ち、未知・改訂された教材は推測変換しません。
問題文・選択肢・ヒント・解説・問題画面の操作ボタンが対象です。通常の画面移動ボタンは学年に合わせた
文字表示のみを使います。保護者向けの分析や保存する問題・回答・問題ID・成績は変わりません。
教材を追加するときは正規表記と、その文脈での読みを確認してください。

クラウド公開前に Supabase の SQL Editor で `supabase_profiles.sql` を実行してください。
非公開の子ども別設定テーブルと算数履歴の読み確認列を追加します。既存履歴の削除・変更はありません。
クラウド設定中の保存失敗時にローカルへ切り替えることはありません。ローカルの表示設定は
`data/profiles.sqlite3` に学習履歴と分けて保存します。

## MVPの範囲と制約

セットの途中で難易度を変える機能、音声読み上げ、外部AIによる評価は未実装です。
学習者選択自体は認証ではありません。公開時は上記の家族用パスワードを有効にしてください。
履歴はユーザーIDで分離し、学習履歴画面には選択した学習者の回答だけを表示します。
履歴の読み込みに失敗した場合は再試行できます。クラウド設定時にローカル履歴へ切り替えることはありません。
ページを再読み込みすると進行中のセットはリセットされますが、保存済み回答は残ります。
DBは起動場所ではなく、このプロジェクトの `data` に保存されます。
回答履歴は保護者画面からJSONでバックアップできます。ローカルDBファイル全体を別途コピーする場合はアプリを停止してください。
開発時のブラウザー検証11回答は `data/mvp-verification.sqlite3` に保管し、
実際の学習に使う `data/history.sqlite3` は空の履歴から始められる状態にしています。
